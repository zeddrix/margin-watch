# Testing rules

Adapted from the Queue project's testing rules, for a small repo.

## ATDD workflow

1. Every behaviour starts as an acceptance criterion in `docs/acceptance-criteria.md`: `AC-NN`, Given / When / Then, with concrete values.
2. Tests are written from the AC, not from the code. Each test name contains its ID (`test_ac07_...`, `test('AC-31 ...')`, `it('AC-40 ...')`) and quotes the AC in its docstring or description.
3. **Red run:** run only the new tests and keep the failure output for `docs/progress.md`. They must fail for the right reason (assertion or NotImplementedError), never import, syntax or fixture errors.
4. **Self-review** with the checklist below. Fix weak tests now, while they're still uncommitted.
5. Commit, tag `tests-approved-<phase>`. From here the tests are frozen.
6. **Green:** implement the smallest code that makes the tests pass. Re-run the same commands, then the full completion gate.
7. **Traceability:** every AC has at least one test; every test cites an AC. `scripts/check_test_integrity.py` enforces this.

## Self-review checklist (before locking a phase's tests)

- [ ] Every AC of the phase has at least one test, and boundary ACs have below / at / above tests.
- [ ] Every test asserts a concrete **value or state**, not just "no exception" or "is visible".
- [ ] **Mutation thought-test:** for each test, name one plausible wrong implementation it would catch. If none, strengthen it.
- [ ] Expected values are written out literally in the test (computed by hand), not computed with the same formula as production code.
- [ ] Failure paths are covered: bad input, missing fields, model error, timeout, malformed file.
- [ ] No test depends on another test, on order, on the real clock, on the network, or on unseeded randomness.
- [ ] Fakes behave like the real thing (same shapes, same exception types).
- [ ] Snapshot files were read line by line and are what a human would want to receive.

## Unit tests (pytest, Vitest)

- Test behaviour through public functions, not private helpers or call order.
- One behaviour per test; Arrange / Act / Assert; descriptive names.
- Boundaries are mandatory: below, exactly at, and above every threshold.
- Fake only what we don't control (model clients, clock, filesystem roots).
- Deterministic: fixed `as_of`, no real clock, an autouse socket guard that fails any Python test opening a network connection, seeded randomness only.
- Builders and fixtures in conftest, small and explicit. No giant shared fixture that hides what a test is about.
- Property tests (hypothesis) for maths invariants.
- Snapshots only for human-readable output (template summary, email HTML), stored as plain files, reviewed as part of the self-review.
- Coverage: 100% lines for `calc.py`, `status.py`, `validate.py`; 90%+ for the package. Coverage is a floor, not the goal.

## E2E tests (Playwright)

- Every test performs at least 2 user actions AND verifies an outcome. "Element is visible" on its own is banned.
- Merge checks that start from the same page into one test instead of many tests that each load the page to check one thing.
- Stable selectors: `data-testid` for key elements. No brittle CSS chains or ambiguous `getByText`.
- Tests use committed fixture run files only (generated by the real CLI from sample data), never live output.
- No `test.skip`, `test.only`, `test.fixme`. Fail loudly.
- Iterate one file at a time; 1 worker, 0 retries. A flaky test is a bug: fix the cause, never add retries or fixed sleeps (wait on state).
- Accessibility with `@axe-core/playwright` on the main page and the open drawer: zero serious or critical violations.

## Enforced by `scripts/check_test_integrity.py`

- Banned: `pytest.mark.skip`, `pytest.mark.xfail`, `pytest.skip(`, `test.skip`, `test.only`, `test.fixme`, `it.only`, `describe.only`, `assert True`, `expect(true)`.
- Playwright `retries` must be 0.
- Every AC ID in `docs/acceptance-criteria.md` has a test, and every test name has an AC ID.

## Enforced by `.claude/hooks/protect_tests.py`

- Committed test files, fixtures and snapshots can't be edited, moved or deleted by the agent.
- The guardrail files can't be changed by the agent.
- Uncommitted (red-phase) test files can be edited freely until they're committed.

## When an approved test seems wrong

Don't work around it. Write in `docs/open-questions.md`: the test, the AC, why it seems wrong, and the exact diff you'd propose. Make sure it isn't the code that's wrong. Then continue with the rest of the plan. Zeddrix decides later, and unlocks with `touch .claude/allow-test-edits` if he agrees.
